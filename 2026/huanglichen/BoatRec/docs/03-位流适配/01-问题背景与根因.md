# 01 问题背景与根因

> 问题定位文档：说明"璞致板 NPU 无法运行"的背景、现象、根因与最终解决路线。
> 最终结论见文末 §6，本目录后续（02/03/05）为展开细节。

## 1 背景

- 璞致板：FMQL100TAI900（PL DDR3 接 BANK33），icraft NPU 推理无法运行
- 目标：让官方 AI 位流适配璞致板 32bit PL DDR，或获得适配的 32bit 位流

## 2 问题现象

- icraft 推理报 `DMA Write time out (5000 ms)`，日志关键字段：
  - `PLDDR_STATUS: 0x0`、`HP_WDMA_NUM: 0`、`DDR_WDMA_NUM: 4`
- 官方 yolov5s demo、yolo26 均复现

## 3 根因

- 璞致板 PL DDR：2 × MT41K256M16-107 = **DQ32**、1GB、DDR3-1600（800MHz）、1.5V
- **复旦微默认的位流为 DQ64**：复旦微 100TAI（v3.31/25060601）参考实现（bywk/BOOT 系列）DDR_MIG app 接口全部 512bit（DQ64），随板默认位流即 64 位 → 与璞致板 DQ32 位宽不匹配，直接用官方推荐位流无法工作
- 改用 **32ddr 位流**（`one_input_wk_display_24030104_32ddr`，下载站提供）：同为 **DQ32、Xilinx MIG** → **DQ 位宽匹配**
- **改用 32ddr 后真正问题**：位流内 DDR_MIG 的**引脚配置与璞致板实际引脚不匹配**（32ddr 参考 vs 璞致板：19 一致 / **52 不同**，仅系统时钟 H9/G9 一致）
- 引脚不匹配 → MIG/DDR 控制器初始化失败 → PL DDR 不可用 → icraft DeviceTensor 依赖 PL DDR（不可绕过）→ NPU 无法运行

> 注：初判曾误以为根因仅是"DQ64 vs DQ32 位宽不匹配、下载站无 32bit 位流"。后续定位到下载站存在 32ddr 位流，位宽问题即解，真正根因修正为**引脚配置**。

## 4 证据链（要点）

- 板上诊断（vs_ddrtest）：`udma`(PS DDR) `tensor.to()` OK；`plddr`(PL DDR) `tensor.to()` 超时 → PL DDR 写路径不可用
- 32ddr 参考工程：MIG 7 Series DataWidth=32，app 256bit，TargetFPGA xc7z100ffg900（对标 FMQL100TAI900）
- 璞致板真实引脚：由 `4_14_PZ_PCIE` 工程（xc7z100ffg900）内 MIG IP 的 xdc 确认，与 `3_10_PZ_DDR` UCF 一致
- 已排查排除项：icraft 版本（3.31.0/3.31.1）、位流加载方式、模型（官方验证过的 yolov5s 同样超时）

## 5 解决路线（实际采用）

**下载站 32 位位流 + 璞致引脚配置**：

1. 取下载站 `04_FPAI/06_临时（谨慎下载）/one_input_wk_display_24030104_32ddr.zip`（32ddr 参考实现，DQ32、xc7z100）
2. 按璞致板真实引脚修改 DDR_MIG 引脚（`02` §4.1）
3. 安装复旦微补丁（7z100ai 数据库，解决 PS7 定制 IP AI_IN，`06`）
4. Procise 综合/实现/出位流 → **璞致引脚版位流 `ai7100_top_puzhi.bit`**
5. 转字节交换 bin → fpga_manager 加载（`03` §5）

## 6 结果

- **位流适配达成**：`ai7100_top_puzhi` 位流加载成功（fpga_manager `operating`）
- **PL DDR 验证通过**：写读一致（`PLDDR OK`，校准成功，不再 DMA timeout）
- 后续阻塞转入 NPU 算子层（32ddr 位流无 Norm/Softmax 硬件算子，custop2 位流已解决，见 `04`）
