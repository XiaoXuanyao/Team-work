## 3 确认璞致板真实 DDR 引脚（关键）

### 3.1 如何获取引脚数据（来源与交叉验证）

|---|---|---|---|
| 来源 A | `4_14_PZ_PCIE`（Vivado 2019.1） | **xc7z100ffg900**（与 FMQL100TAI900 同芯片） | MIG 7S IP 的 `design_1_mig_7series_0_0.xdc` |

## 4 改造生成璞致板位流（改引脚 + 打 ip_patch + 出位流）

### 4.1 改 MIG 引脚

**原理**：MIG 的引脚映射**唯一来源**是配置文件 `mig_a.prj`（`xci/xml` 不含引脚）。文件内 `<PinSelection>...</PinSelection>` 段逐条声明每个 DDR 信号的 `PADName`（物理封装引脚）。改引脚 = 替换该段。

**涉及文件**：

| 角色 | 路径 |
|---|---|
| 目标（32ddr，待改） | `ps_in.srcs\sources_1\ip\mig_7series_0\mig_a.prj`、`ps_in.ip_user_files\mem_init_files\mig_a.prj`（两处需同步替换，替换前备份 `.bak_32ddr`） |
| 源（璞致 PZ_PCIE，正确引脚） | `4_14_PZ_PCIE\...\design_1_mig_7series_0_0\mig_a.prj` |
| 正确产物（可直接用） | `one_input_32ddr解压产物\mig_a_prj_PZ_PCIE引脚版.prj` |

**结构示例**（`<PinSelection>` 段）：
```
<PinSelection>
  <Pin IN_TERM="" IOSTANDARD="" PADName="E10" SLEW="" VCCAUX_IO="HIGH" name="ddr3_addr[0]"/>
  <Pin IN_TERM="" IOSTANDARD="" PADName="J3"  SLEW="" VCCAUX_IO="HIGH" name="ddr3_dq[0]"/>
  ...（每个信号一行，PADName = 物理引脚）
</PinSelection>
```

**操作步骤**：

1. Vivado 2018.3 打开 32ddr 工程基座 `ps_in.xpr`
2. **整段替换 `<PinSelection>`**：打开 32ddr 的 `mig_a.prj` 与璞致 PZ_PCIE 的 `mig_a.prj`，用璞致的**完整 `<PinSelection>...</PinSelection>` 段**覆盖 32ddr 中的对应段，保存。同时同步替换 `ps_in.ip_user_files\mem_init_files\mig_a.prj`
3. **重生成 MIG**：Tcl 执行 `reset_target all [get_ips mig_7series_0]` + `generate_target all`（regenerate 即按新 mig_a.prj 应用引脚）
4. **验证**：生成 `user_design/constraints/mig_7series_0.xdc`，抽查 dq[0]=J3、addr[0]=H7、cas_n=E7、reset_n=E11 等全为璞致引脚，IOSTANDARD=SSTL15_T_DCI（1.5V）
5. 综合 MIG → **0 errors / 0 critical warnings** ✅

**关键注意（为什么必须整段替换）**：

- 32ddr 原版 `mig_a.prj` 的 `<PinSelection>` 是 **DQ64 布局**：含 `ddr3_dq[32..63]`、`ddr3_dm[4..7]`、`ddr3_dqs[4..7]` 等 64bit 残留引脚（复旦微参考仅取低 32bit 用）
- 璞致 PZ_PCIE 版是 **DQ32 布局**：仅 `ddr3_dq[0..31]`、`dm[0..3]`、`dqs[0..3]`，共 75 引脚
- **若只把 `PADName` 改成璞致值、却保留 64bit 残留** → MIG 综合报 **multi-driven 警告**（如 `gen_dq_iobuf[30]/[31]` 同时驱动 `mem_dq_in[0]`，PHY 生成错乱）
- 因此**必须用璞致的完整 `<PinSelection>` 块替换**（顺带删除 64bit 残留），并保留 `<PinSelection>` 段外的 32ddr 属性（`PortInterface=NATIVE`、`DataWidth=32`）

**关键差异示例**（替换前 → 替换后）：

| 信号 | 32ddr 原值 | 璞致 PZ_PCIE 值 |
|---|---|---|
| ddr3_dq[0] | L1 | J3 |
| ddr3_dq[2] | K5 | J4 |
| ddr3_dq[5] | L3 | K6 |
| ddr3_dq[30] | C1 | C4 |
| ddr3_dq[31] | C4 | B2 |
| ddr3_addr[0] | E10 | H7 |
| ddr3_dm[0] | J3 | L1 |
| ddr3_odt[0] | G7 | J10 |
| ddr3_reset_n | G17 | E11 |
| ddr3_dq[32] | K10 | （无，已删） |
| ddr3_dqs_p[4] | L8 | （无，已删） |

### 4.2 打 ip_patch 补丁（复旦微 PS7 数据库）

**背景**：PS7 是复旦微定制 IP，需打复旦微补丁后（`PS7.btl`）才能被 Vivado 解析；直接拿 32ddr 工程在标准 Vivado 打开（未遵循复旦微 UDP 服务器配套说明）会导致 PS7 无法解析 → black box → `DRC INBB-3`。

1. **下载补丁包** `JFM_Kits.zip`（860MB，下载站 `02_A7_K7_Z7_V7补丁（PL必须打补丁）/补丁包/IP补丁/5.3.1.6/`），解压到**英文路径**（如 `patches\JFM_Kits`）；补丁包含 `ip_patch/100ai/unisims/PS7.btl`（定制 PS7 primitive，解决 PS7 解析的关键）
2. **系统环境变量设置** `JFM_PATH = <解压目录>`，**重启 Vivado**
3. **注意：Vivado 需要包含全部 7 系列 + Zynq-7000 器件**；否则 `replace_7z100ai_file` 会报缺 `kintex7.bfd`
4. Tcl Console 加载工具并替换数据库（FMQL100TAI 关键）：
   ```tcl
   source D:/.../patches/JFM_Kits/ip_patch/run.tcl
   replace_7z100ai_file
   ```
   把 Vivado 的 7z100 数据库替换为 **FMSH 7z100ai**（含定制 `PS7.btl`）
5. **重启 Vivado** 使数据库生效（其他命令：`reset_database_to_default` 还原、`database_change_flag` 查状态）
6. **处理工程旧版 ip_patch**：若工程已带旧版（`ps_in/ip_patch/`），先备份移走（`ip_patch.bak_32ddr_v1`），再 `source run.tcl` 从 JFM_PATH 复制新版，否则旧版会拦截
7. **禁用 IP Cache**：工程打开后 `Settings → IP → IP Cache → Cache scope = Disabled`
8. **挂 ip_patch 钩子**：`source D:/.../patches/JFM_Kits/ip_patch/run.tcl`，然后 `add_hook_tcl_to_prj`

### 4.3 DRC 处理：REQP-52/56（GTGREFCLK）

write_bitstream 报 `REQP-52/56 connects_GTGREFCLK_ACTIVE`（GTXE2 用 GTGREFCLK 是复旦微芯片正常设计），降级为 Warning（双保险）：

1. `ip_patch/process_control/write_bitstream_pre.tcl` 末尾追加：
   ```tcl
   set_property SEVERITY {Warning} [get_drc_checks REQP-52]
   set_property SEVERITY {Warning} [get_drc_checks REQP-56]
   ```
2. `ps_in.srcs/constrs_1/7100_peripheral.xdc` 取消注释 REQP-52/56 对应 `set_property SEVERITY {Warning}` 两行

### 4.4 综合实现 + 一键出位流

1. Design Runs里，右键synth2，选择Launch Runs...，进行综合和实现
2. 点 **Generate Bitstream**，ip_patch 在综合/实现/出位流阶段自动运行（MIG re-patch、PS7 用 7z100ai 库）→ 产出 `ps_in.runs/impl_3/ai7100_top.bit`

> 位流产物、格式转换、fpga_manager 加载与上板验证见 03 第5节。
